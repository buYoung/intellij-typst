# 구성과 상태의 공통 패턴

JSONinja와의 일관성은 정보의 배치와 상태 표현에도 적용한다. 아래 패턴은 JSONinja의 온보딩·편집 화면을 분석해 Typst 문서 작업에 맞춘 것이다. 새 UI 기능이나 배치를 구현했다는 뜻은 아니다.

## 작업 → 결과 → 설명

가장 먼저 실제 작업 영역을 보여주고, 결과와 설명을 가까이 연결한다. JSONinja의 전·후 비교 카드와 Typst의 소스·미리보기는 이 관계를 공유한다.

| 상황 | 먼저 보여줄 것 | 대응 규칙 |
| --- | --- | --- |
| 소스와 문서 결과 | 같은 문서의 소스·미리보기 | 예제명·수식·제목이 서로 대응해야 한다. 장식용 다른 문서와 조합하지 않는다. |
| 전·후 비교 | 같은 입력에서 달라진 부분 | 창 크기·배율·문서 위치를 맞춘다. 포맷만 비교할 때 내용까지 바꾸지 않는다. |
| 완성·도움말 | 입력 위치와 실제로 열린 도움말 | 팝업만 떼어 확대해 맥락을 없애지 않는다. |
| 진단 | 오류 위치와 진단 문구 | 색상 강조만 남기거나 오류 내용을 임의 작성하지 않는다. |

같은 비중의 결과는 같은 크기로 제시한다. 한쪽을 크게 보여줘야 하는 경우에는 사용자가 무엇을 판단해야 하는지 이유를 남긴다. JSONinja의 두 열 비교 구조는 [원본 간격](tokens.md)에 근거한다.

## 읽는 순서와 강조

제목은 현재 작업, 본문은 효과, 보조 문구는 조건을 설명한다. 주요 기능의 제목과 조건을 같은 굵기·색으로 나열하지 않는다. 제품 식별은 반복하되 모든 버튼·설명에 로고를 넣지는 않는다.

UI의 실제 선택·포커스·오류 색은 IDE가 맡는다. 브랜드 청록색은 별도 의미를 덮어쓰지 않는다. 소스의 구문 강조와 미리보기 문서의 색도 서로 다른 정보 체계로 유지한다.

## 상태별로 보존할 정보

| 상태 | 표현 기준 | 피할 표현 |
| --- | --- | --- |
| 정상 | 결과와 실행 가능한 동작을 선명하게 보여준다. | 이미 완료된 것처럼 보이는 가짜 진행 표시 |
| 처리 중 | 진행 여부와 현재 문서의 관계를 유지한다. | 이전 결과를 최신 결과로 설명하는 캡션 |
| 비활성 | 플랫폼의 상태 표시와 동작 설명을 따른다. | 모든 비활성 아이콘에 임의의 동일 투명도 적용 |
| 오류 | 오류 위치·이유·가능한 다음 동작을 함께 전달한다. | 빨간 색이나 경고 그림만 남기기 |
| 미리보기 사용 불가 | 환경 조건과 실제 안내를 그대로 보인다. | JCEF가 없는 화면에 정상 미리보기를 합성하기 |

## 밀도가 높을 때

제품 기능을 설명하는 데 필요한 창·도구 모음·탭만 남긴다. 코드·수식·진단을 읽을 수 없을 정도로 화면 전체를 축소하지 않는다. 세부 내용을 설명하려면 같은 예제의 상세 장면을 분리한다. 좁은 표시 영역에서는 단순히 글자 크기만 줄이기보다 한 장면이 다루는 기능을 줄인다.

상점용 이미지에서는 [구성과 문구](visual-assets/composition-and-copy.md), 실제 아이콘에서는 [구성 요소 기준](components/icons.md)이 이 패턴을 구체화한다.
