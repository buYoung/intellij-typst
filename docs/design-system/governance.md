## 확정한 방향과 남은 작업

사용자는 T·청록색을 유지하면서 T를 닌자화하되, 너무 튀지 않고 JSONinja 로고와 일관되게 표현하도록 선택했다. 이어 하찮고 멀뚱한 표정의 시안 중 02번 ‘모여 있는 눈’을 로고로 선택했다. 로고의 선택 기록은 [자산 원본](visual-assets/asset-system.md#확정한-로고-원본), 고정할 형태는 [시각 언어](visual-assets/visual-language.md)에 반영했다. 작은 IDE 아이콘은 v3의 틀·선·테마 체계를 유지한다.

선택한 PNG는 원본 그대로 보관했다. 남은 제작 사항은 이 형태를 보존한 로고 SVG·테마 파생본, 파일 아이콘, 편집 가능한 상점 템플릿과 실제 제품 캡처, IDE와 게시 크기에서의 최종 확인이다. 로고의 형태 선택은 완료했으며, SVG의 획 수치와 작은 크기의 광학 보정, 워드마크의 실제 글꼴 이름은 후속 제작에서 기록한다.

## 제작 후에 판정할 사항

파일 아이콘을 실제 크기에서 밝은·어두운 테마로 확인하고, 같은 자산을 쓰는 색상 설정 화면까지 추적한다. 작은 기호와 큰 로고는 각 사용처에서 따로 본다. 기능 아이콘을 추가했다면 문서에 연결한 소비자가 새 파일을 실제로 읽는지 확인한다.

형태가 뭉치는 문제는 해당 자산을 먼저 수정한다. 공통 선 굵기나 색의 변경이 필요하면 [값과 연결](tokens.md)과 영향을 받는 자산을 함께 갱신한다. 큰 로고의 문제만으로 IDE 아이콘 전체의 선 굵기를 바꾸지 않는다.

로고의 최종 형태와 상점용 결과 확인은 [시각 자산의 납품 기록](visual-assets/delivery-and-versioning.md)이 담당한다. 문서 구조 검사는 자산 렌더링이나 제품 실행 검증을 대신하지 않는다.
