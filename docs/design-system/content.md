# 제품명과 설명 문구

같은 제품군의 문구는 **기능 이름 → 사용자에게 생기는 결과 → 필요한 조건** 순서로 쓴다. JSONinja의 기능별 설명 구조를 이어받되, 오래된 홍보 문구나 제품에 없는 기능까지 복사하지 않는다.

## 고정 표기

| 항목 | 표기 | 사용 기준 |
| --- | --- | --- |
| 이 제품 | `Typstninja` | 상점 이름·워드마크·이미지의 제품명 |
| 언어·파일 형식 | `Typst`, `.typ` | 제품명과 언어 이름을 구별 |
| 참조 제품 | `JSONinja` | 현재 제품명. 저장소 이름 `json-helper2`는 출처를 설명할 때 사용 |
| 개발자 | `livTeam` | 현재 플러그인 등록의 대소문자 유지 |
| 동작 | `Preview Typst`, `Export Typst` | 실제 IDE 메뉴를 가리킬 때 원문 유지 |

`JSON Ninja`는 참조 저장소 README의 표기이고, 공개 상점은 `JSONinja`를 사용한다. 이를 새 표기 변형을 늘리는 근거로 삼지 않는다. `Typst Ninja`, `TypstNinja`, `Typst Ninja Pro` 등으로 임의 확장하지 않는다.

## 작업 중심으로 쓴다

| 의도 | 사용할 방식 | 피할 방식 |
| --- | --- | --- |
| 기능 식별 | “Typst Preview: 소스와 결과를 함께 확인” | “강력하고 혁신적인 문서 경험” |
| 범위 설명 | “지원하는 선언과 참조 탐색” | “모든 Typst 코드를 완벽하게 이해” |
| 조건 설명 | 미리보기의 런타임·JCEF, 출력의 CLI 조건을 관련 안내에 유지 | “설치만 하면 모든 환경에서 즉시 작동” |
| 진단 | 위치·이유·다음 동작 | 실패를 사용자 탓으로 돌리거나 기술 오류만 나열 |

짧은 캡션에서 모든 조건을 담을 수 없으면 인접한 기능 설명과 연결하되, 캡션 자체가 무조건 지원을 주장하도록 쓰지 않는다. 미리보기와 파일 내보내기는 같은 기능명으로 합치지 않는다.

## 제품군 일관성과 표현의 한계

기능명과 결과를 직접 연결하는 말투, 기술 용어의 정확한 표기, 실제 화면과 맞는 설명을 공유한다. JSONinja의 기존 소개에 있는 최상급·개발 중 항목·긴 탄생 이야기를 Typst의 필수 형식으로 삼지 않는다. 상점 규칙이나 현재 기능과 충돌하는 표현을 유지하는 것은 브랜드 일관성에 도움이 되지 않는다.

게시용 영문 HTML은 [Marketplace 등록 정보](marketplace/jetbrains-marketplace-listing.md), 이미지별 문구는 [구성과 문구](visual-assets/composition-and-copy.md)가 소유한다. 같은 문구를 여러 파일에서 별도로 수정하지 않는다.
