# 아이콘

아이콘은 작은 공간에서 파일 종류나 실행할 동작을 알아보게 한다. 형태는 기능에 맞게 달라지고, 선과 테마 처리에는 [공통 원칙](../foundations.md)과 [원본 값](../tokens.md)을 적용한다.

## 먼저 선택할 원형

| 만들려는 것 | 사용할 원형 | 고정할 부분 | 바꿀 수 있는 부분 |
| --- | --- | --- | --- |
| Typst 파일·언어 기호 | JSONinja `languages/v3` | 16 좌표계의 사각 틀, 모서리, 선, 테마 색 | 내부 언어 글자를 T로 교체 |
| 제품 전용 기능 기호 | JSONinja v3의 동작 표현 | 단색 선, 둥근 끝·연결, 의미 중심 구성 | 문서·미리보기·출력에 필요한 내부 기호 |
| 이미 IDE가 제공하는 실행·다운로드 | 현재 `AllIcons` | 플랫폼의 의미와 상태 처리 | 새 제품 전용 의미가 필요할 때만 별도 변형 검토 |
| 제품 로고 | [브랜드 심볼 기준](../visual-assets/visual-language.md) | 절제된 닌자 형태의 T·청록색, JSONinja의 평면 윤곽 표현 | 큰 크기에 맞춘 시각적 무게와 여백 |

파일 아이콘의 일관성은 같은 틀에서 언어 식별자만 달리하는 방식으로 확보한다. 다른 언어들 사이에서 Typst만 배경이 꽉 찬 타일로 보이게 하지 않는다.

파일·언어 기호는 틀 안의 단순한 T를 유지한다. 로고의 두건·눈매·몸통을 그대로 축소하지 않고, T의 골격으로 제품 식별을 연결한다. 로고의 닌자 표현이 v3 파일·기능 기호의 선 규격을 바꾸지는 않는다.

## JSONinja v3의 도형 구성법

밝은 테마 기능 원본 11개를 비교했다. 모두 같은 틀에 기능을 억지로 끼우는 방식은 아니다.

| 원본 계열 | 실제 구성 | 적용할 규칙 |
| --- | --- | --- |
| 정렬·축약·생성·비교·타입 변환 3종·API 불러오기 | 8개 파일의 앞쪽 두 중괄호 경로가 동일. 내부 기호만 다름 | 같은 제품 맥락의 동작은 공통 외곽을 재사용한다. 외곽을 파일마다 손으로 다시 그리지 않는다. |
| Escape / Unescape | 같은 따옴표·역슬래시 구성에서 더하기/빼기만 달라짐 | 서로 반대되는 동작은 바뀌는 부위만 바꾼다. |
| 파일 열기 | 폴더 외곽과 안쪽 중괄호 | 대상 자체가 중요한 기능은 대상 외곽을 허용한다. |
| 언어 기호 11종 | 같은 사각 틀 안의 `C`, `C+`, `C#`, `Go`, `Jv`, `JS`, `Kt`, `Py`, `Rs`, `Sc`, `TS` | 전체를 문자 폰트로 대체하지 않는다. 원본처럼 간결한 선형 식별자를 사용한다. `C+`는 C++용 원본의 실제 도형 표기다. |

중괄호는 JSON의 의미다. Typst 파일 기호에는 언어 사각 틀과 T를 사용하고, 새 문서 동작에는 그 동작의 대상·방향을 나타내는 요소를 사용한다. “브랜드 일관성”을 이유로 JSON 기호를 Typst 의미로 바꾸어 읽게 하지 않는다.

## 실제 제작 순서

1. 사용처의 크기를 먼저 정한다. 작은 파일 아이콘은 언어 원형, 작업 창과 제품 로고는 해당 역할의 규격을 따른다.
2. [언어 틀과 선 값](../tokens.md)을 고정하고 내부 기호만 구성한다. T는 기존 파일 아이콘의 내부 범위를 출발점으로 삼고 선형으로 정리한다.
3. 같은 SVG 구조에서 밝은·어두운 색을 바꾼다. 별도 수작업으로 두 도형을 만들지 않는다.
4. 실제 크기에서 외곽 틀과 T가 붙거나, 화살표와 다른 기호가 합쳐지는지 본다. 필요한 광학 보정은 해당 기호에서 하고 원형 전체를 바꾸지 않는다.
5. 배포 경로와 실제 소비자를 연결한 뒤 파일 목록·탭·설정·테마 전환을 확인한다. 이 단계는 현재 문서 작성에서 실행한 작업이 아니다.

## 선과 세부 요소의 제한

열린 화살촉과 둥근 선 끝은 원본 v3의 방식이다. 굵은 채움 삼각형·입체 화살표를 섞지 않는다. 축약의 작은 점처럼 선 굵기와 같은 지름을 갖는 채움은 [명시적 예외](../tokens.md)로 사용한다.

원본에는 소수 좌표와 광학적 비대칭이 있다. 좌표를 모두 정수로 반올림하거나, 언어 기호마다 같은 글자 폭을 강요하지 않는다. 다만 같은 역할의 원형·선·테마를 달리하는 변경은 개별 아이콘의 장식으로 처리하지 않는다.

상점용 제품 로고는 [다른 자산](../visual-assets/asset-system.md)이다. 파일 아이콘을 바꾸는 것만으로 제품 로고가 바뀌지는 않는다.

## 변형·크기·상태

기본·어두운 테마 변형은 같은 기호를 사용한다. 현재 `icons/typst.svg`에는 대응하는 `_dark` 파일이 없다. v3 색상 쌍을 도입할 때는 어두운 테마 파일도 제작하고, 실제 선택 여부를 확인해야 한다.

크기는 [IntelliJ Platform 조건](../platforms/intellij-platform.md)을 따른다. 비활성·선택 상태의 색이나 투명도를 새 고정값으로 정하지 않고 플랫폼 표시와 함께 검토한다. 아이콘 변경으로 실행·미리보기·내보내기의 동작을 바꾸지 않는다.

| 상태 | 유지할 것 | 별도 확인 |
| --- | --- | --- |
| 기본·어두운 테마 | 경로·틀·기호 의미 | 테마 파일의 선 색 선택 |
| 선택·활성 | 플랫폼 선택 표시와 기능 의미 | New UI의 활성 배경 위 식별성 |
| 비활성 | 같은 기호와 동작 이름 | 사용 불가 상태가 활성처럼 보이지 않는지 |
| 확대·축소 | 종횡비와 도형 관계 | 실제 소비 크기에서 틈·획·점의 구별 |

원본 비교판은 [밝은 배경](../references/jsoninja-reference-light.png)과 [어두운 배경](../references/jsoninja-reference-dark.png)에 있다. 각 항목의 1·2·3배 렌더링을 비교한 분석 자료이며, 새 Typst 아이콘의 납품 파일은 아니다.

## 사용과 검증

- 아이콘의 의미는 동작 이름·설명과 함께 전달한다. 기존 `Preview Typst`, `Export Typst` 문구와 서로 다른 동작 기호를 대응시킨다.
- 회색의 밝기만 달리해 다른 기능을 표현하지 않는다. 의미가 겹치면 외곽이나 내부 기호를 구별한다.
- 소스 편집 영역이나 컴파일 결과에 브랜드 장식을 덧씌우지 않는다. 작은 기호는 주변 IDE 요소와 같은 작업 맥락에서 읽혀야 한다.
- 적용 후 파일 목록·설정 화면, 밝은·어두운 테마에서 식별성과 연결을 확인한다. 확대 SVG가 선명하다는 사실만으로 작은 크기의 가독성을 통과 처리하지 않는다.

현재까지의 확인 결과는 [적용·검증 기록](../governance.md)에 있다.
