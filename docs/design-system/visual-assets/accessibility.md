# 시각 자산의 가독성

청록색과 선 스타일은 내용을 읽고 구별할 수 있는 범위에서 사용한다. 작은 IDE 아이콘의 가독성과 큰 상점 이미지의 가독성은 따로 확인한다.

색 쌍의 수치와 로고·일반 글자의 적용 차이는 [공통 대비 기준](../accessibility.md)이 소유한다. 밝은 배경에서 청록색 작은 글자를 쓰거나, 로고의 예외를 캡션에 적용하지 않는다.

| 확인 대상 | 판정 기준 | 문제가 있을 때 |
| --- | --- | --- |
| 로고 | 밝은·어두운 배경에서 T의 주요 획과 외곽을 알아볼 수 있다. | [색의 역할](visual-language.md)과 배경을 확인하고, 획·여백을 조정한다. |
| 동작 기호 | 색을 제외해도 동작을 구분할 수 있다. | 형태와 실제 동작 이름을 함께 사용한다. |
| 제품 화면 | 배포된 표시 크기에서 핵심 코드·수식·UI 문구가 읽힌다. | 불필요한 영역을 줄이거나 상세 장면을 분리한다. |
| 설명 문구 | 화면 내용에 묻히지 않고 충분한 대비를 가진다. | 문구를 화면 밖으로 옮기거나 배경과 배치를 조정한다. |
| 진단·강조 | 색만으로 결과·오류의 의미를 전달하지 않는다. | 실제 메시지와 위치의 대응을 남긴다. |

## 내보낸 이미지에서 확인할 것

편집 원본의 큰 화면뿐 아니라 실제 게시 크기와 축소된 목록 맥락에서 본다. 코드·수식·설명 문구 중 읽어야 할 내용을 먼저 정하고, 그 부분이 흐려지면 그림자나 장식 대신 장면의 범위와 배율을 수정한다.

검은 캡션 띠는 불투명하게 유지해 밑의 구문 강조색에 따라 대비가 바뀌지 않게 한다. 긴 캡션을 별도 정보 띠로 옮길 때도 화면을 과도하게 줄이지 않는다. 좌우 비교는 단순히 빨강·초록만으로 구분하지 않고 상태 이름이나 실제 결과를 함께 제시한다.

영상이나 움직이는 설명을 만들 경우 정적인 대표 장면에서도 기능을 이해할 수 있게 한다. 동작과 결과가 지나치게 빨리 지나가지 않게 하고, 텍스트로 설명할 수 있는 핵심 조건을 영상에만 남기지 않는다.

원본 색의 대비 계산과 기존 자료의 육안 검토는 수행했다. 새 Typst 자산의 최종 출력·게시 크기별 검증은 제작 후에 수행한다. 제품 전체의 접근성 인증을 달성했다고 주장하지 않는다.
