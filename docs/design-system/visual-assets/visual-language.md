# 시각 언어

Typstninja의 로고는 **청록색 T에 가까이 모인 점눈을 넣은, 하찮고 멀뚱한 닌자**다. T의 가로획·세로획에 두건과 얼굴을 통합하고, JSONinja 로고의 윤곽선과 평면 채움 표현을 공유한다. 2026-09-26 사용자는 이 느낌의 10개 시안 중 02번 ‘모여 있는 눈’을 선택했다. [확정한 로고 원본](asset-system.md#확정한-로고-원본)이 형태의 기준이다.

로고의 직접적인 형제 원본은 JSONinja의 패키지 로고다. 작은 IDE 아이콘은 기존에 선택한 v3 체계를 따른다. 로고의 표정·실루엣·하단 두 곡선은 선택한 PNG를 기준으로 고정한다. SVG 경로·획 수치·테마 파생본은 이 형태를 보존하면서 실제 표시 크기에 맞춰 제작한다.

## 공통 표현

| 분류 | 기준 | 적용과 확인 |
| --- | --- | --- |
| 불변 | `T`의 실루엣과 닌자 얼굴을 하나의 심볼로 통합한다. | 먼저 T의 골격을 읽을 수 있고, 두건과 눈매에서 닌자 성격이 드러나야 한다. |
| 불변 | JSONinja 로고의 윤곽선·제한된 평면 채움·두건 속 눈매를 공유한다. | [참조 로고와 채택 범위](asset-system.md)를 비교한다. 작은 기능 기호의 선 굵기를 로고에 그대로 고정하지 않는다. |
| 불변 | 청록색을 로고·상점 이미지의 브랜드 강조에 사용한다. | 실제 UI와 문서 출력의 색을 브랜드 색으로 덮어쓰지 않는다. |
| 가변 | 로고, 정보형 이미지, 실제 화면은 역할에 맞게 밀도와 브랜드 강조량을 달리한다. | 로고는 식별, 화면 이미지는 제품 사용 증거가 먼저 읽혀야 한다. |
| 조건부 | 배경의 밝기와 표시 크기에 따라 색·세부 요소를 조정한다. | 기본·어두운 배경에서 같은 T가 유지되고, 축소해도 눈과 두건이 뭉치지 않아야 한다. |
| 금지 | JSON 글자·중괄호·무기와 과장된 동작을 새 로고에 옮기지 않는다. | JSONinja와 공유할 것은 닌자 표현의 방식이다. T의 식별을 가리는 장식은 덜어낸다. |
| 검증 | 로고 단독과 실제 제품 화면 옆에서 모두 같은 인상을 유지한다. | 확대 원본, 축소 표시, 밝은·어두운 배경을 구분해 확인한다. |

## 유지할 색의 출처

| 출처 | 확인한 값 | 이후 역할 |
| --- | --- | --- |
| [기본 로고](../../../src/main/resources/META-INF/pluginIcon.svg) | 청록색 `#239DAD` | 밝은 배경에서 사용하는 브랜드 색의 출발값 |
| [어두운 테마 로고](../../../src/main/resources/META-INF/pluginIcon_dark.svg) | 청록색 `#39B8C6` | 어두운 배경에서 사용하는 브랜드 색의 출발값 |
| 두 기존 로고 | 흰색 `#FFFFFF`의 T | 기존 배색의 관측값. 새 닌자화 로고에서 흰 T를 그대로 써야 한다는 뜻은 아니다. |
| JSONinja 패키지 로고 | 검정 윤곽·채움과 회색 `#CED0D6` | 닌자 형태를 구분하는 중립색 표현의 출처. 새 로고에서는 배경별 식별성을 확인한다. |

작은 IDE 기능 아이콘에는 [v3의 회색 쌍](../tokens.md)을 적용한다. 청록색 유지 선택은 모든 기능·비활성·오류 상태를 청록색으로 바꾸라는 의미가 아니다.

## T를 닌자로 표현하는 법

가로로 펼쳐진 상단과 중앙의 세로획이 로고의 뼈대다. 상단에는 두건과 눈이 드러나는 틈을 통합하고, 세로획은 간결한 몸통처럼 이어지게 한다. 얼굴을 별도로 붙여 T가 가려지지 않게 하며, 글자의 폭과 세로축을 유지한 채 곡선과 내부 빈 공간으로 성격을 만든다.

| 부위 | 제작 기준 | 과해지는 징후와 조정 |
| --- | --- | --- |
| 전체 실루엣 | 넓은 상단·중앙 세로획으로 T가 먼저 읽힌다. | 머리가 원형으로 부풀어 T의 가로획이 사라지면 상단의 가로 구조를 되살린다. |
| 두건·얼굴 가림 | T 상단의 외곽과 내부 경계가 두건·마스크 역할을 함께 맡는다. | 얼굴 주변에 겹테두리와 주름이 쌓이면 닌자를 알아보는 데 필요한 경계만 남긴다. |
| 눈매 | 밝은 얼굴 영역의 중앙에 가까이 모인 검은 점눈 두 개를 둔다. 눈썹·흰 동공·눈꺼풀 없이 멀뚱하고 어설픈 인상을 유지한다. | 반쯤 감긴 반원 눈이나 날카로운 눈매로 바꾸지 않는다. 축소했을 때 두 점이 하나로 붙으면 선택본의 인상을 유지하며 간격을 보정한다. |
| 몸통 | 선택본의 긴 세로획과 하단을 감싸는 두 곡선을 유지한다. | 몸통을 임의로 짧게 만들거나 두 곡선 중 하나를 없애지 않는다. 팔다리와 전신 포즈는 추가하지 않는다. |
| 선과 채움 | 또렷한 윤곽과 평면 채움으로 형태를 구분한다. 끝과 접점은 부드럽게 정리한다. | 내부 묘사가 외곽보다 먼저 보이면 내부선을 줄인다. 얇은 v3 획을 그대로 확대해 로고 전체를 만드는 방식은 피한다. |
| 색 | 청록색으로 T의 주요 형태를 식별하고, 중립색으로 윤곽과 얼굴을 구분한다. | 청록색이 작은 점으로만 남아 기존 식별이 사라지거나, 추가 강조색이 먼저 눈에 띄면 배색 역할을 재조정한다. |

무기·수리검·속도선·길게 휘날리는 띠는 사용하지 않는다. 닌자의 성격은 두건·점눈·두 곡선으로 전달하고, 선택한 T의 비율을 유지한다. 장식 글자나 별도의 캐릭터를 T 옆에 붙이지 않는다.

로고에는 평면 채움을 허용한다. 작은 IDE 아이콘의 `fill="none"`과 획 수치는 로고 규격이 아니다. 둥근 사각 틀은 v3 파일·언어 기호의 원형으로 유지하며, 제품 로고 전체를 감싸는 필수 외곽으로 강제하지 않는다.

## JSONinja와 나란히 놓았을 때

JSONinja의 [패키지 로고](asset-system.md)는 두건을 쓴 인물, 얼굴의 빈 공간과 눈, 검정 윤곽·회색 채움, 크게 통합된 JSON 글자로 식별된다. Typstninja는 이 가운데 **글자와 닌자 형태의 결합, 윤곽이 또렷한 평면 그림, 제한된 색**을 이어받는다. T와 청록색은 Typstninja를 구별하는 요소다.

같은 표시 영역에 두 로고를 놓고 외곽의 무게와 채움의 밀도를 비교한다. Typst 쪽의 무기·주름·소품 수를 늘려 JSONinja의 복잡도를 맞추지 않는다. 세부 묘사를 줄인 상태에서도 두건과 눈매, 선·면의 처리에서 같은 제품군으로 읽혀야 한다. 입체 마스코트, 반짝이는 배지, 날카로운 스포츠 팀 엠블럼 표현은 사용하지 않는다.

상점 이미지에서도 같은 심볼을 반복한다. 장면마다 다른 표정이나 포즈를 새로 만들지 않고, 기능 화면의 정보량에 맞춰 로고의 크기와 위치만 조정한다. JSONinja의 이름과 기존 상점 화면을 Typst의 기능 증거로 재사용하지 않는다.

## 배경·글자

상점 이미지의 배경은 실제 화면과 문구가 구별되는 역할을 맡는다. 장식용 그라데이션·입체 효과를 새 공통 표현으로 도입하지 않는다. 문서의 페이지, IDE의 패널, 설명 문구가 서로 다른 정보임을 분명하게 구분한다.

글자로 표시하는 제품명은 `Typstninja`다. 제품명은 기본 UI 계열의 산세리프 굵은 글자, 설명 캡션은 고정폭 계열을 사용한다. 별도의 장식 서체나 손글씨 서체를 추가하지 않는다. 스크린샷 안의 IDE 글꼴·구문 색은 실제 설정을 유지한다. 서체 역할과 최종 출력 기록은 [구성과 문구](composition-and-copy.md)를 따른다.

## 로고·제품명 조합

| 사용 상황 | 구성 | 기준 |
| --- | --- | --- |
| 작은 제품 목록 | 심볼 단독 | T의 골격과 두건·눈매가 남도록 단순화한다. 전체 제품명을 작은 심볼 안에 넣지 않는다. |
| 소개 이미지·문서 표지 | 심볼 + `Typstninja` | 제품명을 한 줄로 두고 심볼과 글자의 시각적 중심을 맞춘다. |
| 기능 화면의 보조 식별 | 작은 심볼 또는 제품명 | 기능 증거를 가릴 정도로 크게 반복하지 않는다. |
| 단색 인쇄·특수 배경 | 단색 파생본 | 도형은 유지하고 배경과 구별되는 한 색으로 표현한다. 색상 파생본은 원본과 함께 확인한다. |

로고 외부에는 다른 글자·테두리가 닿지 않는 공간을 둔다. 얼굴이나 T 안쪽의 빈 공간을 로고 외부 여백으로 오인하지 않는다. 정확한 외곽 여백과 공식 표시 크기는 [납품 규격](stores/jetbrains-marketplace.md)이 소유한다. 대각 회전, 가로세로 비율 변경, 그림자, 광택, 외곽선 중복 추가는 사용하지 않는다.

IDE의 파일·언어 기호는 [v3 틀 안의 T](../components/icons.md)로 표현한다. 파일 목록에서 필요한 언어 식별을 우선하므로 제품 로고의 얼굴·몸통을 그대로 축소해서 넣지 않는다. 제품 로고와 작은 파일 기호는 T의 골격으로 연결한다.

## 청록색의 사용 범위

청록색은 심볼과 제품 식별의 강조에 집중한다. 어두운 IDE 화면, 검은 캡션 띠, 흰 설명 문구가 기본 정보 전달을 맡는다. 청록색 큰 배경을 상점 이미지의 대부분에 깔아 실제 UI를 작은 삽화로 만드는 구성은 채택하지 않는다.

밝은 배경의 작은 설명 문구에 청록색을 쓰면 현재 색의 대비가 부족하다. 브랜드 색을 유지하되 설명은 중립색으로 돌린다. [계산한 대비](../accessibility.md)는 색상 선택의 근거이며 최종 렌더링의 가독성 검증도 필요하다.

## 파생 자산에서 확인할 기준

다음은 선택한 PNG를 SVG·테마 변형·상점 자산으로 적용할 때의 판정 기준이다. 원본의 선택은 완료했으며, 작은 표시 크기와 실제 제품 환경의 검증은 별도로 수행한다. 기존 분석용 비교판을 새 로고의 검증 결과로 취급하지 않는다.

| 확인 상황 | 충족해야 할 결과 | 실패하면 먼저 조정할 것 |
| --- | --- | --- |
| 제품명 없는 심볼 | T의 골격과 닌자 성격을 함께 알아볼 수 있다. | 상단·세로획의 연결, 얼굴이 차지하는 범위 |
| JSONinja 로고와 같은 표시 영역 | 두건·눈매·평면 윤곽의 표현이 이어지고 시각적 무게가 과하게 튀지 않는다. | 외곽선과 채움의 균형, 내부선의 밀도 |
| 상점의 작은 표시 크기와 확대 원본 | 눈·마스크의 틈이 뭉치지 않고 T의 가로획과 세로획이 구별된다. | 장식 삭제, 빈 공간과 획의 광학 보정 |
| 밝은 배경과 어두운 배경 | 같은 실루엣과 청록색 식별이 유지되고 윤곽·눈이 배경에 묻히지 않는다. | 테마별 중립색과 내부 대비 |
| 제품 화면 옆의 보조 로고 | 기능·결과·캡션이 먼저 읽히고 로고가 안정적으로 제품을 식별한다. | 로고의 배치·크기, 강조색의 면적 |
| 단색 파생본 | 청록색을 제거해도 T와 얼굴의 빈 공간이 유지된다. | 색 경계에만 의존한 형태 분리 |

실제 확인 결과와 확정한 원본 값은 [납품 기록](delivery-and-versioning.md)에 남긴다.
