# 이미지 구성과 문구

방문자는 먼저 “무엇을 할 수 있는가”를 이해하고, 실제 화면에서 그 근거를 확인할 수 있어야 한다. 기본 구성은 **실제 IDE 작업 화면 + 검은 캡션 띠 + 흰 고정폭 문구**다. T·청록색은 제품 식별에 사용한다. 이는 사용자가 선택한 JSONinja와의 일관성을 실제 공개 이미지에 맞춰 구체화한 제작 기준이다.

## JSONinja에서 채택한 표현

공개 이미지의 정렬·축약·이스케이프 장면은 어두운 편집 화면, 짧은 기능 이름, 검은 사각 설명 영역과 흰 굵은 고정폭 문구를 반복한다. 실제 조회한 이미지와 치수는 [관측 기록](stores/jetbrains-marketplace.md)에 있다.

이 중 화면을 크게 보여주는 방식, 높은 대비의 설명, 기능별 한 장면이라는 구조를 채택한다. 캡션이 코드 일부를 가리는 배치와 이미지마다 조금씩 다른 높이는 그대로 반복하지 않는다. 외부 상점의 흰 페이지 배경·파란 설치 버튼·헤더 글꼴은 운영자가 제공하는 화면이므로 제품 브랜드 토큰에 포함하지 않는다.

## 기본 구성과 변형

| 구성 | 사용할 때 | 실제 배치 기준 |
| --- | --- | --- |
| 작업 화면 + 캡션 | 입력 위치와 결과가 한 장면에서 이해될 때 | 화면의 핵심 영역을 크게 유지한다. 캡션은 내용이 없는 하단 공간에 좌측 정렬한다. |
| 작업 화면 + 별도 정보 띠 | 코드·수식·문서가 하단까지 차 있을 때 | 캡션을 화면 밖의 검은 정보 띠로 분리한다. 제품 화면을 가리거나 캡처를 세로로 압축하지 않는다. |
| 소스·결과 비교 | 문서 편집과 렌더링 관계를 보여줄 때 | 실제 분할 편집 화면을 우선한다. 두 별도 캡처라면 문서·배율·상태의 대응을 유지한다. |
| 상세 기능 확대 | 작은 완성 창·진단·도움말을 설명할 때 | 동일 예제에서 필요한 영역을 확대하고, 어디의 상세 화면인지 제목으로 연결한다. |

한 장면 안에서 작업 영역과 결과 영역의 관계를 유지한다. 캡션의 폭은 읽을 문장의 길이에 맞추고, 화면 전체를 덮는 큰 광고 패널로 바꾸지 않는다. 제목·로고·캡션을 서로 다른 모서리에 흩어 놓지 않는다. 화면, 캡션, 제품 식별 영역의 역할은 [자산 체계](asset-system.md)가 소유한다.

## 글자 규칙

| 텍스트 역할 | 글자 계열·강조 | 줄바꿈과 정렬 |
| --- | --- | --- |
| 제품명 | 기본 UI 계열 산세리프, 굵게, 정확한 `Typstninja` 표기 | 한 줄. 심볼과 함께 놓으면 시각적 중심을 맞춘다. |
| 이미지 기능명 | 고정폭 계열, 굵게 | 캡션의 시작에 배치한다. 기능명 자체를 여러 줄로 찢지 않는다. |
| 기능 결과 설명 | 같은 고정폭 계열 | 문장·의미 단위로 줄바꿈한다. 경로·옵션·제품명 중간을 자르지 않는다. |
| 제한·환경 조건 | 같은 계열 또는 인접한 본문 | 읽을 수 있는 크기를 유지한다. 작게 숨기기보다 설명을 분리한다. |
| 실제 코드·IDE 글자 | 캡처한 제품의 글꼴·구문 색 | 홍보용 글꼴로 다시 그리지 않는다. |

글꼴 패밀리가 특정된 편집 원본은 확보하지 못했다. 기능 캡션은 촬영에 사용한 IDE 편집기의 고정폭 글꼴 계열을 사용해 조합을 줄이고, 최종 편집 원본에는 실제 글꼴 이름·굵기·크기를 기록한다. 이 규칙은 “나중에 아무 글꼴이나 선택”하라는 뜻이 아니다. 장식체·손글씨·별도 둥근 광고체를 섞지 않는다.

캡션은 검정 `#000000`과 흰색 `#FFFFFF`를 기본 조합으로 채택한다. 반투명 캡션은 밑의 코드 색에 따라 대비가 달라지므로 기본형에 사용하지 않는다. 청록색은 T 심볼 등 식별 요소에 쓰고, 설명 전체를 청록색으로 바꾸지 않는다.

## 정보의 우선순위

| 역할 | 구성 기준 | 이유 |
| --- | --- | --- |
| 기능을 보여주는 이미지 | 핵심 동작을 짚는 짧은 문구와 해당 화면을 가까이 둔다. | 문구와 증거를 연결해서 읽게 한다. |
| 소스·결과 비교 | 같은 문서임을 알아볼 수 있게 대응 부분을 유지한다. | 편집과 결과의 관계가 제품 가치이기 때문이다. |
| 제품 식별 | 동일한 T와 제품명을 반복 사용하되 화면보다 강하게 강조하지 않는다. | 브랜드를 알아보면서도 기능 판단에 필요한 내용을 볼 수 있게 한다. |
| 상세 기능 | 핵심 장면에서 이해하기 어려운 도움말·진단은 별도 확대 장면으로 다룰 수 있다. | 모든 기능을 한 화면에 작게 모으는 것을 피한다. |

정확한 배치 좌표는 아직 없는 템플릿에서 가져올 수 없다. 템플릿을 제작하면 [원본·영역 지도](asset-system.md)에 먼저 등록하고 이 문서가 이를 참조한다. 제출 크기와 여백은 [상점 규격](stores/jetbrains-marketplace.md)을 따른다.

## 이미지 문구의 의미

다음은 기본 영문 이미지에 사용할 문구 초안과 한국어 의미다. 실제 촬영 장면의 기능·조건과 맞는지 확인한 뒤 줄바꿈을 고정한다. 기본 언어는 [현지화 기준](localization.md)을 따른다.

| 장면 | 기본 영문 문구 | 한국어 의미·조건 |
| --- | --- | --- |
| 분할 편집 | `Typst Preview: See your document beside its source.` | 소스와 문서를 함께 확인. 런타임·JCEF 조건을 기능 설명에 유지 |
| 완성·도움말 | `Typst Completion: Find suggestions as you write.` | 작성 중 제안 확인. 실제 지원 범위의 완성 목록 사용 |
| 진단 | `Typst Diagnostics: Locate problems in your document.` | 문제 위치 확인. 실제 진단과 소스 위치 대응 |
| 출력 | `Typst Export: Save your document in the format you need.` | 원하는 형식으로 출력. 구성된 CLI와 실제 출력 형식만 표시 |

검증하지 않은 속도·성능 수치, 최상급 표현, “설정 없이 모든 환경에서 작동” 같은 문구는 사용하지 않는다. 제품명·식별자·IDE 메뉴 이름은 확인한 표기를 유지한다.

## 배경과 가독성

문구를 코드나 수식의 중요한 부분 위에 겹치지 않는다. 실제 출력 문서의 여백을 브랜드 카피 영역으로 임의 해석하지 않는다. 화면과 문구가 경쟁하면 글자를 무조건 줄이기보다 내용을 줄이거나 장면을 나눈다. 색·가독성 확인은 [접근성 기준](accessibility.md)을 따른다.

## 잘못된 결과를 고치는 기준

| 보이는 문제 | 이유 | 수정 방향 |
| --- | --- | --- |
| 청록색 배경 위에 작은 IDE 캡처만 놓임 | 기능 증거보다 색과 장식이 먼저 보임 | 실제 화면을 주인공으로 돌리고 식별 요소에만 청록색 사용 |
| 긴 검은 캡션이 결과를 가림 | 참고 이미지의 단점까지 복제한 상태 | 설명을 줄이거나 별도 정보 띠로 이동 |
| 프레임마다 글꼴·그림자·모서리가 달라짐 | 같은 도구군의 문법이 사라짐 | 같은 캡션 스타일과 편집 원본 사용 |
| 좋은 장면이지만 코드가 읽히지 않음 | 전체 화면을 과도하게 축소함 | 장면의 범위를 좁히거나 상세 장면 분리 |
| 완성된 것처럼 보이는 가짜 결과 | 실제 기능과 표현이 달라짐 | 실행 가능한 동일 예제에서 다시 촬영 |
