# 스크린샷과 제품 장면

상점 이미지는 Typstninja로 어떤 일을 할 수 있는지 실제 화면으로 보여준다. 아래는 [README](../../../README.md)와 [plugin.xml](../../../src/main/resources/META-INF/plugin.xml)에 근거한 **촬영 후보**이며, 현재 실행·촬영을 마친 결과 목록이 아니다.

## 보여줄 작업

| 장면 | 방문자가 이해할 내용 | 화면 근거와 표시 조건 |
| --- | --- | --- |
| 소스와 결과를 함께 보는 분할 편집 | Typst 코드를 쓰면서 문서 결과를 확인한다. | 같은 문서의 소스와 실제 미리보기를 대응시킨다. JCEF를 사용할 수 있는 환경에서 촬영한다. |
| 작성 중 완성·문서 도움말 | IDE 안에서 Typst 작성 지원을 받는다. | 실제로 나타난 완성 목록이나 도움말을 사용한다. 지원하는 심볼 범위를 전체 언어의 무제한 지원으로 확대하지 않는다. |
| 참조·선언 탐색 | 문서와 코드의 연결을 따라간다. | 실행 가능한 예제에서 해당 기능을 직접 사용한다. 정적 이미지에서 확인할 수 없는 이동 과정은 문구로 과장하지 않는다. |
| 진단과 수정 | 문제 위치를 확인하고 문서를 고친다. | 실제 진단이 발생한 원인과 수정 결과를 연결한다. 오류 표시를 장식으로 만들어 넣지 않는다. |
| 출력 | 작성한 문서를 내보낸다. | 구성된 Typst CLI로 수행하는 명시적 내보내기임을 유지한다. 결과 파일이 생성된 뒤에 촬영한다. |

이 표는 자산 개수나 상점의 고정 순서를 정하지 않는다. 상점의 배치 조건은 [상점 규격](stores/jetbrains-marketplace.md)이 담당한다.

## 기본 장면 세트와 연결

초기 제작은 아래 네 가지 기능 역할을 기준으로 구성한다. 이는 제품의 편집 방향이며, 운영자가 요구하는 이미지 개수나 이미 제작한 파일 목록은 아니다. 기능을 합치더라도 각 역할의 증거가 작아져 읽히지 않는 구성은 피한다.

| 역할 | 보여줄 화면 | 성공한 장면의 조건 | 캡션과의 관계 |
| --- | --- | --- | --- |
| 대표 장면: 소스와 미리보기 | 제목·문단·수식이 있는 문서의 분할 편집 | 소스와 같은 제목·수식이 결과 페이지에 보임 | 제품의 주된 가치를 설명 |
| 작성 지원 | 짧은 문서에서 열린 완성 목록 또는 도움말 | 입력 위치와 제안의 관련성이 보임 | 기능 이름과 작성 효과를 연결 |
| 문제 확인 | 실제 진단이 붙은 소스와 메시지 | 오류 위치·메시지·해결 맥락이 함께 보임 | “진단이 있음”보다 무엇을 판단할 수 있는지 설명 |
| 출력 | 출력 설정·동작과 실제 생성된 결과 | 포맷·대상 문서가 확인되고 파일이 실제 생성됨 | 미리보기와 파일 내보내기를 구분 |

추가 탐색 장면이 필요하면 대표 장면에 모든 팝업을 넣지 말고 별도 상세 화면으로 연결한다. 한 화면에 여러 기능 이름을 넣어 목록처럼 만드는 구성을 기본형으로 사용하지 않는다.

## 촬영 세션을 고정한다

같은 이미지 세트는 같은 IDE 테마·창 크기·편집기 글꼴·배율·예제 문서를 기준으로 촬영한다. JSONinja의 어두운 작업 화면을 기본 표현으로 이어받고, 밝은 테마는 실제 읽기 환경을 설명하는 별도 변형으로 둔다. 운영체제 바탕화면이나 다른 제품 창은 캡처 범위에 넣지 않는다.

사용자 이름·개인 경로·토큰·실제 업무 문서를 샘플로 쓰지 않는다. 짧고 재현 가능한 예제를 사용하고, 기능에 필요한 오류 외에는 불필요한 진단·알림을 정리한다. 사용자가 실제로 보지 못하는 팝업·메뉴를 합성하지 않는다.

기능 캡션·제품명·T 심볼은 실제 제품 화면과 분리된 편집 요소로 관리한다. 같은 화면을 번역하거나 다른 비율로 내보낼 때 제품 화면을 다시 만들어내는 일을 줄인다.

## 예제 선택

저장소에는 [마크업 예제](../../../samples/verify/00-markup.typ)와 [수식 예제](../../../samples/verify/04-math.typ)가 있다. 기능 재현의 출발점으로 검토하되, 가독성 좋은 홍보용 문서로 이미 승인된 자료는 아니다.

[전체 검증 문서](../../../samples/verify.typ)는 로컬 패키지 fixture를 전제로 한다. 설정 없이 그대로 실행되는 상점용 예제라고 소개하지 않는다. 촬영용 문서는 실제 제품에서 열고 렌더링한 뒤 소스와 결과가 일치하는지 확인한다.

## 실제 동작을 보존하는 기준

- 구문 강조, 완성 창, 오류 표시, 문서 결과는 실제 제품에서 나온 화면을 사용한다.
- 미리보기는 JCEF 사용 가능 여부에 영향을 받는다. 모든 IDE 환경에서 같은 미리보기가 제공된다고 설명하지 않는다.
- 언어 서비스와 선택적 런타임의 차이를 유지한다. 외부 도구가 필요한 출력 기능을 무설정 내장 기능으로 표현하지 않는다.
- 창을 과도하게 축소해 기능보다 장식이 더 잘 보이는 구성을 피한다. 필요한 화면 영역을 선택하되 해당 기능의 맥락을 남긴다.

정적인 화면과 움직임 설명을 함께 만들게 되면 같은 예제와 상태를 사용한다. 영상 제작 여부와 길이·업로드 방식은 현재 제작 결정과 [상점별 조건](stores/jetbrains-marketplace.md)을 확인한 뒤 정한다.

## 동작 설명의 리듬

JSONinja의 로컬 온보딩에는 7개 GIF가 있고 모두 800×571이다. 분석한 대표 프레임은 [탭·기능·비교 창](../references/jsoninja-onboarding-reference.png)을 보여준다. 이 자료는 현재 v3 아이콘을 모두 사용하는 화면이라는 증거는 아니다.

동작 설명은 시작 상태 → 한 동작 → 결과를 알아보는 정지 구간으로 구성한다. 화면 전환을 장식적으로 빠르게 반복하지 않는다. 실제 처리 속도를 보장하는 수치처럼 보일 수 있는 인위적인 배속·생략은 설명 없이 사용하지 않는다. 반복 영상의 첫 장면과 끝 장면은 무엇이 초기화되는지 이해할 수 있어야 한다.

정적 이미지에서도 같은 기능의 핵심 결과를 이해할 수 있게 한다. 영상의 정확한 길이·파일 형식·제출 방식은 후속 제작 계약과 상점 문서에서 정하며, 온보딩 GIF 길이를 광고 영상의 필수 길이로 복사하지 않는다.
