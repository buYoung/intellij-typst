# 아이콘의 시각 원칙

일관성의 기준은 작은 아이콘에서 JSONinja v3의 **공통 틀·선 처리·시각적 무게·테마 대응**, 로고에서 JSONinja의 **닌자 표현과 평면 윤곽**, 제품 UI에서 **기본 글꼴과 정보 위계**, 홍보 이미지에서 **실제 작업 화면과 명확한 캡션**이다. 2026-09-26 사용자는 T를 닌자화하되 너무 튀지 않고 JSONinja 로고와 일관되게 표현하도록 요청했다. Typstninja는 T·청록색을 유지하며 이 방향을 적용한다.

## 유지할 것과 달라질 것

| 분류 | 규칙과 이유 | 확인 방법 |
| --- | --- | --- |
| 불변 | 제품 전용 작은 아이콘은 투명 바탕의 단색 윤곽선으로 그린다. 축약 기호의 점처럼 의미에 필요한 작은 채움은 허용한다. 큰 채움 도형만 두드러지는 것을 피한다. | [원본 값과 채움 예외](tokens.md)를 비교한다. |
| 불변 | 선 끝과 연결부는 둥글게 처리한다. 단순·복합 도형에서 같은 선 언어를 유지한다. | `stroke-linecap`, `stroke-linejoin`과 실제 축소 결과를 확인한다. |
| 가변 | 외곽 형태와 내부 기호는 기능에 따라 달라진다. v3에도 중괄호형, 폴더형, 언어별 기호가 공존한다. | 색을 제외해도 파일·미리보기·내보내기의 의미가 구분되는지 확인한다. |
| 조건부 | 밝고 어두운 테마에서는 색을 바꾸고 의미와 도형 구조를 유지한다. | 같은 이름의 기본·`_dark` 파일을 비교한다. |
| 조건부 | 작은 파일 아이콘과 큰 제품 로고는 각각의 사용 크기에 맞게 정리한다. | [환경 조건](platforms/intellij-platform.md)과 [로고 역할](visual-assets/asset-system.md)을 따로 확인한다. |
| 금지 | v3 적용 아이콘에 그라데이션, 입체 음영, 큰 배경 타일을 추가해 별도 스타일을 섞지 않는다. | 원본과 달리 장식이나 채움이 먼저 보이면 선 형태로 단순화한다. |
| 검증 | 수치 일치만으로 완성 판정을 내리지 않는다. 선이 끊기거나 내부 공간이 뭉치면 실제 크기에서 다시 다듬는다. | [대표 상황](governance.md)을 확인한다. |

## Typst에 적용할 때

현재 파일 아이콘은 청록색 바탕과 흰색 `T`로 이루어져 있다. 이는 기존 제품 식별의 근거이고, v3 선 스타일을 이미 충족하는 자산은 아니다. 새 파일 아이콘에서는 Typst를 식별할 수 있는 기호를 유지하면서 [v3 값](tokens.md)을 적용한다. 구체적인 획과 외곽은 제작 결과를 보고 확정한다.

기본 실행·다운로드 동작처럼 IDE가 이미 제공하는 기호는 [기존 사용처](components/icons.md)를 출발점으로 삼는다. 제품군 일관성을 이유로 플랫폼의 공통 의미와 상태 표시를 다시 그리지는 않는다.

제품 로고의 심볼·브랜드 색상 결정은 [상점 시각 언어](visual-assets/visual-language.md)가 소유한다. 이 문서의 작은 아이콘용 회색과 선 굵기를 큰 로고·제목·본문 전체에 기계적으로 확대 적용하지 않는다.

## JSONinja 자료의 역할을 구분한다

같은 저장소에 있는 자료라도 서로 다른 시기의 표현을 담고 있다. 최신 파일명이나 보이는 인상만으로 전부 하나의 디자인 규칙에 합치지 않는다.

| 조사한 자료 | 확인한 특징 | Typst에 가져올 것 |
| --- | --- | --- |
| `icons/classic/v3`, `icons/expui/v3` | 기능별 11개와 테마 변형. 윤곽선·색·끝 처리가 일치하고 대응 파일은 동일 | 기능 기호의 선 문법, 같은 의미의 기호 재사용, 테마 쌍 |
| `icons/languages/v3` | 11개 언어가 동일한 둥근 사각 틀을 사용하고 안쪽 글자만 교체 | Typst 파일 아이콘의 가장 가까운 형제 원본 |
| `META-INF/pluginIcon.svg` | 중괄호·JSON 글자·닌자·무기가 결합된 복합 그림 | 로고의 두건·눈매·윤곽과 평면 채움, 글자와 캐릭터를 결합하는 표현. JSON 글자·중괄호·무기는 옮기지 않음 |
| `icons/*/toolWindowIcon-*` | 중괄호와 교차 기호, 채움형 경로. v3 선택과 별개로 사용 | 역할별 아이콘이 다를 수 있다는 근거. v3 선 굵기의 원본은 아님 |
| `ai/png/jsoninja.png`, `type_converter.png` | 2px 선과 별도 회색·파랑·초록을 표기한 과거 시안 | 기능 비교 방식만 참고. 현재 v3의 색·선 규격으로 채택하지 않음 |
| 온보딩 코드·GIF | 기본 IDE 위젯, 제목·본문·보조문구의 위계, 어두운 작업 화면 | [글자·간격 체계](tokens.md), [작업 흐름 표현](patterns.md) |
| 형제 제품의 공개 상점 이미지 | 실제 IDE 화면 위의 검은 정보 띠와 흰 고정폭 문구 | [상점 이미지 구성](visual-assets/composition-and-copy.md) |

출처별 위치와 조사 한계는 [검증 기록](governance.md), 공개 상점의 관측 자료는 [상점 문서](visual-assets/stores/jetbrains-marketplace.md)에 있다.

## 제품군에서 같아야 하는 것

| 층위 | 공통으로 유지 | Typst에서 달라지는 부분 |
| --- | --- | --- |
| 로고 식별 | 글자와 닌자 형태의 결합, 또렷한 윤곽과 제한된 평면 채움, 제품명 표기 방식 | 절제된 닌자 형태의 T, 청록색, 단순화한 세부 요소 |
| 파일·언어 기호 | 둥근 사각 틀, 동일한 획, 테마별 회색 | 틀 안의 언어 식별자 |
| 기능 기호 | 동작 의미가 먼저 읽히는 단색 선, 같은 도형의 반복 사용 | 미리보기·출력·문서 탐색을 나타내는 내부 기호 |
| 실제 UI | IDE 글꼴·배경·포커스·선택 상태를 따른다. | Typst 편집·결과 문서·진단에 필요한 정보 |
| 홍보 이미지 | 실제 작업 화면, 높은 대비의 캡션, 기능명과 결과의 대응 | JSON 데이터 대신 Typst 소스·수식·페이지 결과 |

같은 도구군이라는 인상은 이 층위들이 함께 만든다. 모든 기호에 중괄호를 붙이거나 모든 화면을 청록색으로 채우는 것은 공통성이 아니다.

## 검토할 때의 우선순위

먼저 사용자가 같은 기능을 같은 의미로 읽는지 본다. 그다음 선·틀·테마·글자 위계가 원본과 연결되는지 본다. 마지막으로 자산별 크기와 실제 배경에서 선명도를 확인한다. 의미를 흐리는 장식, 작은 글자, 과밀한 캡션은 브랜드 색을 정확히 썼더라도 수정 대상이다.
